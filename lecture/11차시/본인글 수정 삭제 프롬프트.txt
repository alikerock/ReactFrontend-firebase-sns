main-feed 페이지의 게시글 카드에 작성자 권한에 따른 수정/삭제 기능을 추가해줘.

현재 로그인 기능과 Firestore 게시글 조회 기능은 이미 구현되어 있으며,
기존 main-feed 페이지의 디자인과 레이아웃은 최대한 유지한다.

[구현 요구사항]

1. 작성자 권한 확인
- Firebase Authentication의 현재 로그인 사용자 정보를 사용한다.
- currentUser.uid와 각 게시글 데이터에 저장된 작성자 UID(authorUid)를 비교한다.
- 두 UID가 일치하는 게시글에만 [수정], [삭제] 버튼을 표시한다.
- 다른 사용자가 작성한 게시글에는 수정/삭제 버튼이 나타나지 않도록 한다.
- 로그인하지 않은 상태에서는 수정/삭제 버튼이 나타나지 않도록 처리한다.

예시 조건:
currentUser?.uid === post.authorUid


2. 수정 버튼 구현
- 본인이 작성한 게시글의 [수정] 버튼을 클릭하면 해당 게시글을 수정할 수 있도록 한다.
- 기존 프로젝트에 게시글 작성/수정 폼 또는 관련 컴포넌트가 있다면 이를 우선 재사용한다.
- 수정 화면에는 기존 게시글의 제목, 내용 등 현재 데이터를 기본값으로 표시한다.
- 저장 시 Firestore의 updateDoc()을 사용하여 해당 게시글 문서를 수정한다.
- 게시글 전체를 새로 생성하지 말고 기존 Document ID를 유지한다.
- 수정 완료 후 목록 페이지 또는 게시글 상세 화면에서 변경된 내용이 바로 확인되도록 한다.
- 수정 실패 시 console에서 오류를 확인할 수 있도록 처리한다.


3. 삭제 버튼 구현
- 본인이 작성한 게시글의 [삭제] 버튼을 클릭하면 바로 삭제하지 말고
  사용자에게 삭제 여부를 확인한다.

예:
"게시글을 삭제하시겠습니까?"

- 확인을 선택한 경우에만 Firestore의 deleteDoc()을 사용하여 게시글을 삭제한다.
- 취소를 선택하면 아무 작업도 수행하지 않는다.
- 삭제 성공 후 목록 페이지에서 해당 게시글이 즉시 사라지도록 한다.
- 삭제 실패 시 console에서 오류를 확인할 수 있도록 처리한다.


4. UI
- Edit / Delete 버튼은 MyPosts.jsx 스타일을 그대로 참고한다.
- 게시글 카드의 기존 디자인은 변경하지 않는다.
- 게시글 카드 하단의 좋아요/댓글 영역과 자연스럽게 배치한다.
- 본인의 글에만 수정/삭제 버튼이 나타나도록 conditional rendering한다.
- 기존 반응형 레이아웃이 깨지지 않도록 한다.


5. Firestore
수정:
- doc()
- updateDoc()

삭제:
- doc()
- deleteDoc()

방식으로 구현한다.

예시 형태:

const postRef = doc(db, "posts", post.id);

await updateDoc(postRef, {
  title,
  content,
});

await deleteDoc(postRef);


6. 주의사항
- 기존 로그인 기능을 변경하지 않는다.
- 기존 Firestore 게시글 조회 기능을 변경하지 않는다.
- 현재 게시글 데이터 구조와 필드명을 먼저 확인한 뒤 구현한다.
- 작성자 UID 필드명이 authorUid가 아니라면 기존 프로젝트에서 실제 사용 중인 필드명을 사용한다.
- 불필요한 컴포넌트나 파일은 수정하지 않는다.
- 새로운 라이브러리는 설치하지 않는다.
- 기존 MUI 스타일과 컴포넌트를 최대한 재사용한다.
- 먼저 현재 프로젝트의 게시글 데이터 구조와 Home.jsx 관련 코드를 확인한 후 필요한 부분만 수정한다.
