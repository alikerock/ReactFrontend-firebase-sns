현재 프로젝트에서 사용자에게 메시지를 표시하기 위해
window.alert() 또는 alert()를 사용하고 있는 부분을 전체적으로 점검해줘.

기존 alert() 중심의 메시지를 상황과 중요도에 따라
MUI의 Snackbar, Dialog, Alert를 활용하도록 개선해줘.

적용 기준은 다음과 같다.

1. Snackbar
- 게시글 등록 완료
- 게시글 수정 완료
- 댓글 등록·삭제 완료
- 좋아요 처리 완료
- 이미지 업로드 완료
- 사용자 확인이 필요하지 않은 간단한 성공 메시지

→ 화면 흐름을 방해하지 않도록 일정 시간 후 자동으로 사라지게 처리

2. Dialog
- 게시글 삭제 여부 확인
- 댓글 삭제 여부 확인
- 이미지 삭제 또는 교체 등 되돌리기 어려운 작업
- 사용자의 명확한 확인이 필요한 작업

→ 확인 / 취소 버튼을 제공하고
→ 확인을 선택한 경우에만 실제 Firebase 작업 실행

3. Alert
- Firebase 작업 실패
- Firestore 또는 Storage 권한 거부
- 로그인하지 않은 사용자의 접근
- 필수 입력값 누락
- 네트워크 및 데이터 처리 오류

→ 사용자가 실패 원인이나 필요한 조치를 이해할 수 있는 메시지 표시

추가 조건:
- 현재 사용 중인 alert() 위치를 먼저 확인한 후 적절한 UI로 교체한다.
- 기존 Firebase 기능과 화면 구조는 유지한다.
- 현재 프로젝트가 MUI를 사용하고 있으므로 MUI 컴포넌트를 활용한다.
- 불필요한 컴포넌트나 파일은 수정하지 않는다.
- Snackbar, Dialog 등의 open 상태는 React State로 관리한다.
- Firebase 비동기 작업은 기존 try...catch...finally 구조를 유지한다.
- 처리 중에는 버튼을 비활성화하여 중복 요청을 방지한다.
- catch에서 발생한 오류는 console.error()도 유지한다.
- 수정한 위치와 어떤 alert()를 어떤 UI로 변경했는지 마지막에 정리해줘.
